Agentic IDAM PoC Architecture

The PoC rig as built: no agent provider, Raidiam as the Trust Controller, PingFederate as the bank's authorisation server. October 2026.

Agents are registered in an agent marketplace, identified through OpenID Federation with Raidiam as the Trust Controller, attested on SPIRE's word, and given sender-constrained tokens by PingFederate. A gateway and a policy decision point check every call, and Shared Signals carry lifecycle events to enforcement within seconds.

Everything runs in one protected network, a single Docker host in the PoC. It calls out to Raidiam, and nothing outside can call in except PingFederate, through its public issuer.

The rig

Trust boundaries

  • Raidiam (external) is the single source of who an agent is and what it may do: its software statement, certified keys, roles (the capability envelope) and SPIFFE binding. Every party trusts an agent only through a chain to Raidiam's pinned trust anchor.
  • The protected network holds PingFederate, the agents, the resources, the gateways and the PDP, SPIRE, OpenBao and the marketplace. It makes outbound calls only: Raidiam lists and vouches for its entities, but cannot fetch them.
  • PingFederate's issuer is public (the ngrok tunnel in the PoC). Raidiam and other federation members fetch PingFederate's Entity Configuration from it, and PingFederate's token endpoint trusts its own attester by fetching it there too.

Main flows

Deploying a Principal version

  1. The operator approves a Principal version in the marketplace.
  2. The marketplace creates a Federation managed software statement in Raidiam. Raidiam gives it its identifier and hosts its Entity Configuration.
  3. It adds the SPIFFE binding to the statement: spiffe://example.org/agent-<first 8 characters of the statement id>, SPIRE's key endpoint, and PingFederate as its attester.
  4. It creates the agent's bridge key in OpenBao. OpenBao makes and signs the CSR, and Raidiam certifies it.
  5. It adds the agent's roles (its capability envelope) and a SPIRE entry for its workload label, then waits until Raidiam vouches for it. Nothing is registered in PingFederate.

An attested token request

  1. The agent's container gets a JWT-SVID from SPIRE, addressed to PingFederate.
  2. It asks PingFederate's attester for a client attestation. The attester checks the SVID against SPIRE's live keys, and against the binding Raidiam publishes for the agent.
  3. The agent calls PingFederate's token endpoint with the attestation and a DPoP proof (attest_jwt_client_auth).
  4. PingFederate trusts the attester through its federation chain. If it has not seen the agent, it resolves the agent's chain to Raidiam's anchor and registers it.
  5. PingFederate signs a bridge private_key_jwt for the agent with its key in OpenBao, and issues an access token for one resource, bound to the instance key.

Agents calling agents

  1. The Principal finds the Accounts or Payments agent by capability through the federation, and calls its MCP endpoint through the agents' gateway and the PEP.
  2. The sub-agent, attested under its own SPIFFE ID, exchanges the Principal's token at PingFederate (RFC 8693): sub stays the Principal, act names the sub-agent.
  3. It calls its resource with the new token, bound to its own instance key. The resource's gateway, the PEP and the PDP check the call, and the resource checks both agents' chains in Raidiam.

Suspending an agent

  1. The operator suspends a version in the marketplace.
  2. Raidiam's statement becomes Suspended, and its authority stops vouching for the agent.
  3. PingFederate's transmitter raises a Shared Signals account-disabled event. The PEP picks it up within a poll and refuses the agent's tokens.
  4. Reinstating reverses both.

What is PoC-only

The rig demonstrates the trust model; these are its shortcuts, each with a production equivalent in demo/raidiam/PROTECTED-ENVIRONMENTS.md.

  • One Docker host, with identifiers on host.docker.internal and the rig's own certificate authority.
  • An ngrok tunnel as PingFederate's public issuer.
  • PingFederate in its development profile, as a single node with in-memory state.
  • OpenBao unsealed with a key kept on disk; the sub-agents' keys in files.
  • The marketplace driving Docker through its socket, and an operator's Raidiam session kept in an unauthenticated MongoDB.
  • Raidiam's admin API used with an operator's session until it allows client credentials.
